# Referral agreement review draft

This implementation is disabled unless the existing referral backend is explicitly enabled and service credentials are configured. No database proposal has been applied. Company authorisation and final Nigerian counsel review are required before launch. The draft identifies no invented registration number or representative and provides no Forge countersignature.

The agreement is per school referral. Terms in `terms.json` use the full first school contract value, deduct only actual internet, direct school operation expenses and tax, exclude salaries and pay 15% once on first-deposit receipt in week four of resumption. The fourth-week marker is resumption plus 21 days, not an unconditional promise of payment on that date. A recorded school contract plus signed upload are required for commencement; upload review is a separate evidence check. Full correct payment discharges only the corresponding agreement; accrued audit/correction/fraud claims, unpaid balances and other referrals survive.

Authenticated routes:

- `GET /api/referrals/payout-profile` returns the owner's bank name, account name and masked account number. `POST` registers the profile once; reviewed correction is an operational prerequisite. Full account number is never returned to the client or included in generic account responses. The proposal grants no browser access to these tables.
- `GET /api/referrals/agreement?referralId=...` returns evidence/status. Adding `&download=1` checks the active owner, serves the PDF with private/no-store headers and records its immutable version, original content hash and database served timestamp. Each download has an append-only history record. This records service delivery, not saving to a device.
- `POST /api/referrals/agreement` accepts a multipart PDF, referralId, exact version and `signedDeclaration=true`. It checks origin, confirmed-email authentication, active ownership and a recent matching download. Maximum file size is 5 MB, streamed body limits do not trust Content-Length, paths use server UUIDs, storage is private and upload cannot overwrite. A transaction lock reserves one upload; completion records database time and SHA-256. Object deletion and reservation cancellation are attempted if database completion fails.
- `POST /api/referrals/statement-request` locks the referral and returns an idempotent pending receipt with database receipt time and the fifth working day. `GET ?referralId=...` retrieves the owner's latest receipt. Weekends and a reviewed Nigerian public-holiday table are excluded. An unconfigured or insufficient holiday calendar fails closed and directs the referrer to contact Forge; it never supplies a made-up deadline. Holiday coverage is intentionally unseeded pending official-source review.

Before live use, validate the SQL against an isolated database and exercise foreign-owner requests, concurrent uploads, storage failure/database failure cleanup, unauthenticated access, revoked accounts, download/upload history and holiday coverage. A process crash or failed cleanup may strand a reservation/object: staff reconciliation is required, and an uploaded record must never be silently reopened. A private-bucket lifecycle/retention policy, monitoring, payout-detail correction audit, staff statement fulfilment and payment/review operations remain operational review work. No end-to-end or live database validation is claimed.

The conservative PDF check rejects known active actions, embedded-file tokens, encrypted/object-stream PDFs and decoded escaped action names. It is not a complete PDF parser or malware scanner, and timestamps/hashes do not validate an electronic signature. The UI therefore says uploaded, awaiting review. Staff must inspect the externally signed document, unchanged terms, signing evidence, school contract and deposit receipt. Downloading this public generic draft exposes no school's private fees; completed particulars remain in the private uploaded document.

Electronic-signature review references: [Evidence Act, section 93](https://www.kadunajudiciary.org/assets/resources/Evidence-Act.pdf), [Evidence (Amendment) Act 2023](https://sabilaw.org/wp-content/uploads/2023/08/EVIDENCE-AMENDMENT-ACT-2023.pdf). These support review of electronic/digital evidence, not a guarantee of enforceability or authenticity of any particular upload.

Verification: `node --test tests/referral-policy.test.mjs tests/referral-agreement.test.mjs` covers commission amounts/rounding, week-four marker, payout validation, masking, known PDF rejection cases, streamed bounds and holiday/weekend deadlines. Integration adds the generated PDF font-stream acceptance check. Public build and browser verification are recorded separately under document-review/.
