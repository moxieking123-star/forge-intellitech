# School proposal: private delivery

The seven-page proposal is generated by `scripts/build-school-documents.py` into ignored `private-assets/forge-school-proposal-2026-10-22-v1.pdf`. It contains the confirmed NGN10,000 per child per term fee, including taxes. It is not beneath `public/`, has no public download route and is not linked from the public website. The public overview remains a non-commercial introduction.

`/programmes/resources#proposal` asks for name, school, email and specific delivery consent. It does not subscribe the visitor to marketing. Its same-origin API validates a bounded 4 KB body, rejects the honeypot, uses durable Upstash limits (email: two/hour; deployment-set IP: eight/hour; global: 100/hour) and sends a fixed private PDF attachment through authenticated Zoho SMTP with TLS. Rate keys use HMAC identifiers; analytics are disabled. The message is warm and written from the programmes team, with the enquiry copied privately to programs@forgeintellitech.com. No user-supplied attachment, sender or destination URL is accepted.

Secure configuration required before activation:

- `SCHOOL_PROPOSAL_EMAIL_ENABLED=true` only after delivery testing.
- `ZOHO_SMTP_HOST`: the correct regional Zoho SMTP hostname for the mailbox.
- `ZOHO_SMTP_PORT=465` (TLS) or `587` (required STARTTLS).
- `ZOHO_SMTP_USER=programs@forgeintellitech.com` and its SMTP app password in `ZOHO_SMTP_PASSWORD`.
- `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`, a random `PROPOSAL_RATE_SECRET`. Configure rate-key expiry/retention in the service as required.
- `NEXT_PUBLIC_SUPABASE_URL`, server-only `SUPABASE_SERVICE_ROLE_KEY` and `SCHOOL_PROPOSAL_BUCKET`. Create a private bucket with no public/browser read policy; upload the reviewed PDF as `forge-school-proposal-2026-10-22-v1.pdf`. Never make this fee document public. No bucket was created or file uploaded remotely in this work.
- Local development only can use an absolute `SCHOOL_PROPOSAL_PATH` instead of storage; production always uses the private bucket.

Test with a designated recipient: actual arrival and attachment, programme mailbox copy, SPF/DKIM/DMARC, spam handling, failure responses, invalid/cross-origin/oversized requests and repeat requests. SMTP acceptance confirms hand-off, not final inbox delivery. Delivery is not enabled in this preview; the form reports unavailable rather than claiming a send. No real email was sent by development checks. Manual WhatsApp sharing remains available; WhatsApp API delivery awaits its own setup.

Runtime dependency audit after compatible security updates reports zero production advisories; seven development-tool findings remain around Tailwind 3's build chain. A Tailwind 4 migration is breaking and was not forced into this change. Review build tooling before release. Primary framework advisories: https://github.com/vercel/next.js/security/advisories .
